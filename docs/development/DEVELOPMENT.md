# Development Guide

> Rewritten for the current `core/`-first structure (v1.6.5). Supersedes `agent/DEVELOPMENT.md` and `_backup/docs/DEVELOPMENT.md`.

## Stack

- **Language:** Vanilla JavaScript (ES6+), CommonJS only in `scripts/` (Node tooling)
- **UI:** Plain HTML + CSS (custom properties / design tokens), no framework, no transpiler
- **Mobile:** Capacitor 8 (`@capacitor/android` + app/filesystem/haptics/local-notifications/share plugins)
- **External API:** `https://api.alquran.cloud/v1` (surah metadata only, cached)
- **CI:** GitHub Actions → GitHub Pages (Node 20)
- **Tests:** none yet — `npm test` is a stub; only `scripts/test-storage-migration.js` exists

## Dev Setup

Prerequisites: Node.js (20 recommended), npm; Android Studio + JDK 17/21 + Android SDK only if touching Android.

```bash
git clone https://github.com/hadealahmad/MonthlyQuran.git
cd MonthlyQuran
npm install
```

### Run on dev (web/PWA)

The web shell is the repo root (`index.html`) loading synced code from `www/core`. After editing anything in `core/`, re-sync first:

```bash
npm run sync          # copies core/ → www/core, chrome/src/core, firefox/src/core (+ patches android plugins)
```

Then serve with any static server from the appropriate directory:

```bash
# serve the PWA build output
npx http-server www -p 8080
# or python
python -m http.server 8000 --directory www
```

Notes:
- Service worker requires HTTP(S) — use `localhost`, never `file://`.
- For quick logic iteration you can also open `index.html` via a local server at the root; the SW is only active under `www/`.

## Where to Edit

**Always edit `core/`** — never edit `www/core`, `chrome/src/core`, or `firefox/src/core`; they are deleted and regenerated by `scripts/sync.js`.

Platform-specific (do not sync over):
- Extension manifests, `*/src/popup/*`, `_locales/`
- `www/index.html`, `www/sw.js`, `www/manifest.json`
- `android/` native project files

## Scripts Reference (`package.json`)

| Command | What it does |
|---|---|
| `npm run sync` | `sync.js` (core → 3 destinations) + `patch-android-plugins.js` |
| `npm run build` | Full pipeline: version-sync → core sync → extension zips → cap sync android → gradle assembleDebug |
| `npm run build:extensions` | Generates icons and zips chrome/firefox into `build/` |
| `npm run android:run` | Sync + `npx cap run android` |
| `npm run android:build` | Gradle debug APK |
| `npm run android:build:release` | Gradle release bundle (.aab) |
| `npm run sign:android` / `build:apk:signed` | Signing scripts |
| `npm run open:android` | Open project in Android Studio |

## Coding Conventions

- No modules/bundlers: every shared file attaches globals to `window` (see bottom of `constants.js`). Load order in the HTML shells matters.
- Storage access is always `async` through `Storage.*` / `StorageAdapter` — never touch `localStorage` directly.
- Use `Logger` (`core/js/utils/logger.js`) instead of bare `console`.
- All user-facing strings go through `i18n.js` with `data-i18n` attributes (ar + en).
- Dates are handled by `DateUtils` in `algorithm.js` using device-local time; don't hand-roll `toISOString().split('T')[0]` except where it already exists.
- CSS: use the design-token variables from `themes.css` (see [../design/STYLING.md](../design/STYLING.md)); no hard-coded colors.

## Adding a New Feature (checklist)

1. Implement in `core/js/` (new constants → `constants.js`, exposed on `window`).
2. Add UI to the relevant shell HTML(s): `www/index.html` and/or `chrome/src/popup`, etc.
3. Add translations for both `ar` and `en` in `i18n.js`.
4. Style with tokens in `core/css/`.
5. Run `npm run sync`, then test on web before extensions/Android.
6. Bump version in `package.json` and run `node scripts/version-sync.js` (or full `npm run build`).

## Debugging

- Web: DevTools → Application tab for storage keys & service worker cache.
- Extensions: `chrome://extensions` / `about:debugging` inspect the popup.
- Android: `chrome://inspect` with `capacitor.config.json` debugging flag enabled during dev.
