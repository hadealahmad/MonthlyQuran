# Browser Extensions (Chrome & Firefox)

Both extensions share the same architecture: a thin shell around synced `core/` code.

## Layout (identical for `chrome/` and `firefox/`)

```
chrome/  (or firefox/)
├── manifest.json          # MV3 (Chrome) — version stamped from package.json
├── src/
│   ├── core/              # ← generated by scripts/sync.js (DO NOT edit)
│   ├── popup/popup.html   # extension entry point, loads core js/css
│   └── popup/popup.css    # fixed popup window dimensions & popup-specific overrides
│   └── lib/browser-polyfill.min.js   # Firefox only: Promise-based browser API
├── _locales/ar|en/messages.json  # store-listing / UI locale metadata
├── icons/                 # generated by build-extensions.js
├── css/, js/, assets/     # legacy copies kept alongside src/core (see note)
└── assets/fonts/          # Quranic fonts
```

> **Note:** Both directories contain an older flat `js/` + `css/` copy **and** the newer `src/core/` copy. The build system syncs to `src/core`; verify which set each platform's manifest/popup actually references before relying on the legacy files. Cleaning this duplication is a recommended follow-up task.

## Differences

| | Chrome | Firefox |
|---|---|---|
| Manifest | V3 | V3/V2 per manifest |
| API namespace | `chrome.*` callbacks | `browser.*` promises via polyfill |
| Icon sizes | 16/32/48/128 | 16/32/48/96 |
| Reminders | `chrome.alarms` + background script | equivalent via polyfill |

## Development

```bash
npm run sync                 # refresh src/core in both shells
# Chrome: chrome://extensions → Load unpacked → select chrome/
# Firefox: about:debugging → This Firefox → Load Temporary Add-on → firefox/manifest.json
npm run build:extensions     # zip both into build/
```

## Permissions

Defined per-browser in each `manifest.json`. If you add a new capability in `core/`, update **both** manifests and re-check store review requirements.
